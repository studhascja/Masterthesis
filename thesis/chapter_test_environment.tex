\chapter{Test Environment}
In this chapter, the test environment is examined in more detail.
In the following, the terms test environment, test system, and operating system are used. 
The test environment comprises both the test system and the operating system. 
The test system refers exclusively to the applications that are part of the test environment and run on top of the operating system. 
Accordingly, the test system does not include the underlying hardware or the operating system itself.

This chapter is divided into the three parts requirements, test system and the operating system. 
A detailed analysis of the requirements is provided at the outset, as they serve as the basis for both the development of the operating system and the test concept. 
Thus, the requirements constitute the foundation for the overall design of the test environment.
Afterwards the operating system, as it forms the foundation on which the test system will later be implemented, will be described.
Finally, the test system itself will be discussed in more detail.

\section{Requirements}
In this section, the requirements of the test environment are analyzed in greater detail. 
The discussion begins with a description of the system architecture, followed by an outline of general real-time requirements. 
These are then used to define the specific requirements applicable to the test system.

The test environment is illustrated in Figure \ref{fig:pi_wifi_general}. 
It consists of two Raspberry Pi 5 devices, whose exact composition is described in detail in Chapter \ref{sec:used_hardware}. 
One Raspberry Pi acts as the server, while the other functions as the client. 
Both devices run the same operating system.

\begin{figure}[ht]
    \centering
     \includegraphics[width=0.8\textwidth]{figures/Pi_general.drawio.pdf}
    \caption{Outline of the overall test environment}
    \label{fig:pi_wifi_general}
\end{figure}

There are two communication links between the server and the client.
One link which transfers \ac{rt-data} and another one for transfering \ac{non-rt-data}.
These two links are illustraded in Figure \ref{fig:pi_wifi_general} in blue and red.
These connections are handled by separate programs but operate within the same network. 
The server provides an access point to which the client connects, thereby establishing a peer-to-peer connection.

In summary, the goal of the test environment is to transmit both \ac{rt-data} and \ac{non-rt-data} data over the same wireless network interface. 
While the bulk data throughput should be maximized, the primary focus is to ensure that no real-time violations occur on the real-time connection.

Since the test system is intended to transmit, among normal data, \ac{rt-data}, it must fulfill the requirements of a \ac{rt-system}. 
Therefore, the following section first outlines the general requirements of \acp{rt-system}. 
Subsequently, additional requirements that go beyond standard \ac{rt} criteria and are specifically relevant for this system within the given test environment are discussed in more detail.
